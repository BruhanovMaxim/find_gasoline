# НАЙДИ БЕНЗИН — документация проекта

3D-симулятор выживания с автомобилем. Один HTML-файл, открывается двойным кликом в браузере.
Цель игрока — успевать находить работающие заправки, пока не закончилось топливо.

- **Файл:** `index.html` (~143 КБ, ~2466 строк)
- **Зависимости:** three.js `0.185.1` через `importmap` с unpkg — нужен интернет при запуске
- **Движок:** только three.js, физика своя
- **Ассеты:** ноль внешних файлов, все текстуры и звуки генерируются в рантайме

---

## Запуск

Открыть `index.html` в любом современном браузере. Никакой сборки, сервера и установки не требуется.

Единственная сетевая зависимость — строка импорта:

```html
<script type="importmap">
  {
    "imports": {
      "three": "https://unpkg.com/three@0.185.1/build/three.module.js"
    }
  }
</script>
```

Чтобы получить полностью офлайн-версию, содержимое `three.module.js` и `three.core.js` нужно вшить в файл (+ ~1.2 МБ).

| Действие                    | Клавиатура        | Сенсор                 |
| --------------------------- | ----------------- | ---------------------- |
| Газ                         | `W` / `↑`         | кнопка ГАЗ             |
| Тормоз, задний ход          | `S` / `↓`         | кнопка НАЗАД           |
| Руль                        | `A` `D` / `←` `→` | левый пад (аналоговый) |
| Ручник, срыв в занос        | `Space`           | кнопка РУЧНИК          |
| Пауза                       | `Esc`             | кнопка `II` сверху     |
| Звук вкл/выкл               | `M`               | на экране паузы        |
| Рестарт на финальном экране | `R`, `Enter`      | кнопка                 |

Сенсорное управление включается автоматически при `pointer: coarse` или наличии `ontouchstart`.
`initTouch()` вешает на `<body>` класс `touch` — по нему включается отдельная раскладка HUD.

### Раскладка на телефоне

Низ экрана целиком отдан управлению, информация уходит наверх:

```
 статистика            II          карта с детектором
                    таймер АЗС
 
                                       скорость
 топливо ▮▮▮▮▮▮ 50 л                     НАЗАД
  ( руль )                    РУЧНИК      ГАЗ
```

Правила живут в блоке `body.touch …` и бьют базовые по специфичности, поэтому порядок в файле роли не играет.
Отдельный `@media (max-height:520px)` для альбомной ориентации: правая колонка не помещается, скорость уезжает
вниз по центру — между рулём и педалями там пусто.

## Игровой цикл

1. Детектор показывает силу сигнала до активной АЗС (0–100%), направления не даёт.
2. На мини-карте видна зона поиска — пунктирный круг радиусом 130 м со смещённым центром: станция внутри, но не в середине.
3. Ближе 150 м (`LOCK`, растёт от перков) детектор захватывает цель: появляется метка направления, точная дистанция и точка на карте.
4. Дополнительный ориентир — светящийся луч над АЗС, видимый сквозь туман и плавно гаснущий с 820 м.
5. Подъезд ближе 15 м запускает заправку (1.5 с), начисляются очки, открывается выбор перка.
6. Новая АЗС появляется дальше предыдущей, сложность подрастает.
7. Партия заканчивается либо победой на 20-й заправке, либо пустым баком.

### Начисление очков

```
базовые   = 100 + найдено×25 + процент_бака×60 + остаток_таймера×2
если бак > 50%           → ×2
итог                     → × множитель серии (1…4)
канистра                 = 25 × множитель
занос                    = боковая_скорость × время × 3.2 × множитель
```

## Механики

### Детектор и карта — один прибор

Детектор не отдельная панель, а ободок мини-карты: два круглых прибора рядом занимали слишком много места,
особенно на телефоне. Всё рисуется в той же канве, что и карта, — `drawMinimap()`.

| Что                | Как показано                                                              |
| ------------------ | ------------------------------------------------------------------------- |
| Сила сигнала 0–100 | янтарная дуга по ободку от 12 часов по часовой, полный круг = 100%        |
| Направление        | зелёный треугольник на ободке под курсовым углом — **только при захвате** |
| Дистанция          | подпись внизу круга: `147 М` при захвате, иначе `СИГНАЛ 42%`              |
| Пинг               | CSS-кольцо `#ping` поверх канвы, заводится из цикла вместе со звуком      |

Цвета разведены намеренно: янтарь — сила сигнала, зелёный — захват. Одним цветом метка тонула в шкале.

Геометрия считается от размера канвы, поэтому прибор одинаково выглядит и на 150 px десктопа, и на 104 px телефона:

```js
RING_W = MM*0.055        // ширина ободка
RING_R = MMR-RING_W/2-1  // середина ободка
MAPR   = MMR-RING_W-3    // карта — внутренний круг, по нему идёт clip
MMSCALE= MAPR/460        // обзор остаётся прежним: 460 юнитов
```

Показания считает `detector()` — он нужен и подписи в HUD, и отрисовке, поэтому вынесен отдельно.
Курсовой угол `0` — прямо по носу, как у стрелки прежнего компаса.

### Топливо

- Базовый бак 50 л (`TANK_BASE`), перки увеличивают.
- Полный газ: `0.16 + (v/vmax)^1.5 × 0.80` л/с. Накат: `0.025` л/с — отпускать газ выгодно.
- Бездорожье ×1.35, сложность ×`(1 + найдено×0.08)`, перк экономии ×0.88 за штуку.
- **Резерв:** ниже 3 литров скорость ограничена 11.5 м/с (≈40 км/ч), но расход падает втрое — вместо резкого обрыва получается медленный финальный рывок.
- **Течь:** удар силой выше 19 с вероятностью 55% пробивает бак (−0.34 л/с). Лечится заправкой, канистрой или перком «Ремкомплект».

### Серия

Множитель ×1 → ×4, растёт с каждой заправкой, обнуляется при любом ударе сильнее 6. Умножает все начисления.

### Таймер АЗС

```
max(48, 95 − (найдено−1)×5, дистанция×1.25/20 + 16) + бонус_перков
```

Первая станция — без таймера, это обучение. По истечении станция закрывается и открывается в другом месте.

Третий член — обязательный: **таймер связан с дистанцией**, иначе кривые расходятся. Раньше их было две
независимых — дистанция росла на 85 м за станцию, таймер падал на 5 с, — и они пересекались ровно на 10-й АЗС:

| АЗС | дистанция | таймер | нужна средняя | потолок машины |
| --- | --------- | ------ | ------------- | -------------- |
| 9   | 1040 м    | 55 с   | 23.6 м/с      | 27.7 м/с       |
| 10  | 1125 м    | 50 с   | **28.1 м/с**  | 27.7 м/с       |
| 14+ | 1400 м    | 48 с   | 36.5 м/с      | 27.7 м/с       |

С 10-й станции доехать было физически невозможно: она закрывалась раньше, чем до неё можно добраться,
и переоткрывалась на той же недостижимой дистанции. Партия вставала намертво — снаружи это выглядело
как «новые АЗС перестали появляться».

`1.25` — коэффициент петляния по сетке дорог вместо прямой, `20` м/с — средняя скорость по маршруту
(72% от реального потолка), `+16` с — на поиск точки внутри зоны. С 7-й АЗС именно этот член становится
главным, требуемая средняя держится на 16–17 м/с, и запас к потолку остаётся ~65%.

Напряжение поздней игры при этом никуда не делось, оно просто переехало в топливо — куда и следовало
по замыслу. На 20-й АЗС нужно покрыть 1750 м пути при расходе ×2.6:

| Как ехать                    | Результат                        |
| ---------------------------- | -------------------------------- |
| газ в пол                    | встал на 906 м — так не доехать  |
| накатом, без перков          | встал на 1386 м                  |
| накатом + 2 канистры         | доехал за 81 с, осталось 2.5 л   |
| бак ×2, эконом ×2            | доехал за 81 с, осталось 12.9 л  |

То есть на полном газу поздние станции недостижимы принципиально — накат обязателен, и запаса по таймеру
теперь ровно столько, чтобы накатом было выгодно ехать.

### Перки

После каждой заправки предлагаются три случайные карточки из восьми. Все перки складываются
и берутся повторно; сколько раз перк уже взят, написано на карточке (`УЖЕ ×2`) и в тосте при выборе.

| Перк            | Эффект                               | Накопление     |
| --------------- | ------------------------------------ | -------------- |
| Больше бак      | +6 л к объёму, заливается сразу      | линейно        |
| Экономичный ход | −12% расхода                         | ×0.88 за штуку |
| Мощный детектор | +70 м к радиусу захвата              | линейно        |
| Ремкомплект     | один раз автоматически заделает бак  | +1 заряд       |
| Ночная смена    | +15 с к работе каждой следующей АЗС  | линейно        |
| Зимняя резина   | +1.6 к боковому сцеплению            | линейно        |
| Канистры        | +2 канистры на маршруте (максимум 6) | до потолка     |
| Форсаж          | +12% к максимальной скорости         | ×1.12 за штуку |

Канистр не может быть больше, чем мешей в пуле (6). Раньше перк при упоре в потолок молча не делал
ничего — теперь у него есть `maxed()`, и на максимуме он просто не попадает в выдачу. Это единственный
перк с потолком; если такие появятся ещё, `showPerks()` подстрахован на случай пустого пула.

Зимняя резина складывается, но на асфальте её почти не видно и так и задумано: сцепление там уже 9.2,
боковое скольжение гаснет за 0.25 с. Работает она на грунте (0.50 → 0.37 → 0.30 с) и в дождь (0.86 → 0.64 → 0.51 с).

### Кривая сложности

| Событие                           | Условие                                      |
| --------------------------------- | -------------------------------------------- |
| Обучающая АЗС в 170 м без таймера | первая                                       |
| Барьеры на обочинах               | со 2-й, по 11 штук за заправку, максимум 130 |
| АЗС в полях (45% случаев)         | с 3-й                                        |
| Эпизоды дождя 55–90 с             | с 6-й, вероятность 55% на станцию            |
| Дистанция до АЗС                  | `min(360 + (найдено−1)×85, 1400)`            |
| Таймер станции                    | не меньше времени на дорогу — см. «Таймер АЗС» |

Смена дня и ночи не привязана к прогрессу: это независимый цикл в 300 секунд.

### Рельеф и высоты

Ключевое решение, из которого вытекает половина архитектуры: **высоты берутся не из формулы, а из сетки**.

```js
baseHeight(x, z)   // аналитическая сумма синусов, выположенная вдоль дорог
H[]                // Float32Array (193×193), заполняется из baseHeight
heightAt(x, z)     // интерполяция внутри того же треугольника, что и в геометрии
```

Разбиение квада диагональю `a–c` в `heightAt` буквально повторяет порядок индексов в буфере геометрии. Если этого не делать, дороги проваливаются в холмы, а деревья висят в воздухе — рисуется огрублённый меш, а объекты сажаются на гладкую функцию.

Все объекты, дороги, следы шин, станции и канистры используют `heightAt`, а не `baseHeight`.

Из них 995 окон зажигаются к ночи, 822 остаются тёмными. Коллайдеров — 2707 (деревья, камни, дома, фонари, барьеры).

- контактные тени-пятна под всеми крупными объектами — один инстанс на весь мир

Проверка `onPavement(x, z, margin)` считает расстояние до линий сетки **по обеим осям сразу**. Без неё фонарь с обочины вертикальной дороги оказывается посреди горизонтальной.

### Сетка коллайдеров

Все 2707 коллайдеров разложены по клеткам 60×60 (`grid`, `addCollider`). Всё, что ищет свободное место или проверяет столкновение, ходит через `nearColliders(x, z, fn)` — обход девяти клеток вокруг точки. Самый широкий радиус проверки в игре это 20, поэтому 3×3 гарантированно накрывает всех кандидатов, а перебирать весь мир не приходится: перестановка АЗС с раскладкой канистр ускоряется примерно в 14 раз.

### Озёр нет

В коде была генерация до четырёх водоёмов с вязкой физикой и брызгами, но точка отбраковывалась, если оказывалась ближе 95 юнитов к линии дорог, — а `gridDist()` по построению не превышает 96 при шаге сетки 192. Условие выполнялось примерно раз на девять тысяч попыток при шестидесяти попытках на прогон, и при рабочем сиде не выпадало никогда. Фича вырезана; вместо неё в коде осталась явная прокрутка ГПСЧ на 120 вызовов — ровно столько тратил вырезанный блок, и без неё весь мир сгенерировался бы по другой раскладке.

## Физика автомобиля

Аркадная модель с боковым скольжением. Своя, без cannon-es и Rapier: для «доехать до точки» отзывчивость важнее реализма, а движок добавил бы вес и настройку без выигрыша.

Порядок вычислений в кадре:

```
1. руль сглаживается, угол падает со скоростью
2. кузов доворачивается: yaw += (v / WHEELBASE) × tan(steer) × dt
3. мировая скорость раскладывается в НОВОЙ системе машины → vF (вдоль), vL (поперёк)
4. к vF применяются тяга, тормоз, сопротивление
5. vL гасится сцеплением: vL *= exp(-grip × dt)
6. скорость собирается обратно в мир, позиция сдвигается
```

Занос возникает сам собой: кузов уже повернулся, а скорость догоняет его с задержкой.

`gripMax` — это ограничитель, а не крейсерская скорость: разгон `ACCEL*(1 − vF/gripMax)` уравновешивается
сопротивлением задолго до потолка, машина упирается в ≈27.7 из 42. Поэтому Форсаж масштабирует не только
потолок, но и тягу (`ACCEL*S.spd`) — иначе перк поднимал недостижимую границу и давал +8% вместо обещанных
+12%, а три взятых подряд ощущались как одно.

| Параметр                            | Значение                        |
| ----------------------------------- | ------------------------------- |
| Потолок скорости `gripMax`          | 42, на грунте ×0.62             |
| Реально достижимая скорость         | ≈27.7 (100 км/ч), на грунте 50 км/ч |
| Задний ход                          | 13                              |
| Ускорение / торможение              | 27 / 42                         |
| Максимальный угол руля              | 0.56 рад                        |
| Сцепление: асфальт / грунт / ручник | 9.2 / 4.6 / 1.4                 |
| Дождь                               | сцепление ×(1 − rain×0.42)      |

Столкновения: отскок вдоль нормали, сетка коллайдеров с ячейкой 60 юнитов, проверяются 9 соседних ячеек.

## Графика

Всё сделано без постобработки — `EffectComposer` не подключён.

- **Тональная компрессия** ACES, экспозиция 1.18. Небо рисуется собственным шейдером, поэтому ACES вписан прямо во фрагментный шейдер — иначе горизонт не совпадает по цвету с туманом.
- **Три палитры:** день, закат, ночь. Закатная подмешивается по величине `1 − |2·night − 1|`, то есть на переходе.
- **Суточный цикл** 300 секунд: ~70 с светло, сумерки с 75-й, полная ночь примерно с 100-й по 200-ю, дальше рассвет. Солнце ходит по кругу и опускается к горизонту, тени поворачиваются.
- **Свечение** вместо bloom: аддитивные спрайты и точечные системы с процедурной круглой текстурой. 528 фонарей — одна отрисовка.
- **Солнечные блики** — экранный слой: солнце проецируется на экран, вдоль линии «солнце → центр» расставлены четыре пятна с `mix-blend-mode: screen`.
- **Дождь** — `LineSegments`, хвост каждой капли строится по вектору движения, есть ветер и снос от скорости машины. Плюс брызги по земле, затемнение покрытия на 34% и плёнка воды на камере.
- **Тени** — одна `DirectionalLight`, карта 2048, ортокамера 144×144 юнита, привязанная к машине. Дальше работают контактные пятна.
- **Крены кузова** — клевок от продольного ускорения, крен наружу поворота от руля и бокового скольжения.

| Звук                       | Реализация                                                         |

| Двигатель                  | пила + меандр, частота от оборотов, через ФНЧ                      |
| Покрышки, тормоз           | зашумлённый буфер через полосовой фильтр                           |
| Дождь                      | отдельный шумовой канал через ФВЧ                                  |
| Пинг детектора             | синус 620–1240 Гц, интервал от 1.9 с до 0.16 с по мере приближения |

`AudioContext` стартует только по клику на кнопку старта — этого требует политика браузеров.

Всё изменяемое состояние партии живёт в одном объекте `S`, поэтому `reset()` — это почти сплошной список присваиваний. «Почти» — потому что кольцевой буфер следов шин и позиция камеры лежат вне `S` и сбрасываются отдельно (`clearTracks()`, `camPos` / `camAim` / `camera.fov`).

### Мир детерминирован — и это ограничивает правки

Весь реквизит раскладывается одним потоком `rnd = mulberry32(20260727)`. Любой добавленный, убранный или переставленный вызов `rnd()` в секциях 1–4 сдвигает поток и перетасовывает мир целиком: другие деревья, другие дома, другие фонари. Поэтому проверки вроде `if(...) continue` внутри циклов генерации стоят **после** розыгрыша координат, а не до, и поэтому же вырезанный блок озёр заменён явной прокруткой на 120 вызовов.

Контрольный слепок для проверки после правок — в консоли браузера:

```js
colliders.length                                        // 2707
colliders.map(c=>[c.x.toFixed(3),c.z.toFixed(3)]).join()  // строка обязана совпасть
```

## Производительность

- Треугольников в кадре: ~250 тыс., отрисовок — десятки, а не тысячи, за счёт инстансинга.
- В HUD выведен счётчик FPS.
- На экране паузы переключаются тени и качество (`pixelRatio` 1.75 ↔ 1). Переключение тени требует `material.needsUpdate` — материалы пересобираются обходом сцены.
- Трафик утилизируется за 620 м и появляется в кольце 120–340 м от игрока: на карте всегда живо не больше 15 машин.
- Поиск свободного места (АЗС, канистры) идёт через сетку коллайдеров, а не перебором всех 2707 — перестановка АЗС стоит ~0.1 мс вместо ~1.3 мс. Это важно потому, что перестановка случается не только на экране перков, но и посреди езды, когда АЗС закрывается по таймеру.
- HUD пишет в DOM только изменившиеся значения. Раньше сорок свойств переписывались каждый кадр, включая `innerHTML` у литров, то есть полный разбор HTML шестьдесят раз в секунду.
- Буферы, которые переписываются каждый кадр (дождь, пыль, искры, следы, матрицы трафика), помечены `DynamicDrawUsage`.
- Цвета частиц пыли заливаются в GPU только при спавне, а не каждый кадр.
- Конфетти на экране победы гасит свой полноэкранный канвас, когда все лоскуты долетели, — иначе он композился бы до самого рестарта параллельно с рендерером трофея.

### Что сознательно НЕ оптимизировано

| Место                                          | Почему оставлено как есть                                              |
| ---------------------------------------------- | ---------------------------------------------------------------------- |
| `renderer.render()` под паузой                 | рендерер без `preserveDrawingBuffer`; без перерисовки за оверлеем паузы на части драйверов будет чёрный кадр |
| Мини-карта перерисовывается каждый кадр        | карта вращается вместе с курсом; на 30 Гц появляется видимый рывок поворота |
| Капли дождя — массив объектов, не типизированный | 1200 мономорфных объектов это ~30 мкс на кадр, выигрыш неизмерим        |
| Циклы пыли и искр идут по всему пулу           | 400 итераций с ранним выходом; счётчик живых частиц пришлось бы согласовывать с кольцевым буфером |
| Инстансы не отсекаются по одному               | у всех `InstancedMesh` ограничивающая сфера накрывает карту целиком, поэтому в тень попадает вся геометрия; поинстансное отсечение требует прокси-мешей — отдельная работа |

## Принятые решения и их причины

| Решение                               | Почему                                                                |
| ------------------------------------- | --------------------------------------------------------------------- |
| Своя физика вместо cannon-es / Rapier | аркадное управление настраивается быстрее, детерминировано, ноль веса |
| Высоты из сетки, а не из формулы      | иначе дороги тонут в холмах, а объекты висят                          |
| Свечение спрайтами вместо bloom       | 90% эффекта без второго прохода рендера                               |
| Детектор вместо компаса со стрелкой   | со стрелкой «найти» превращается в «доехать по азимуту»               |
| Дождь эпизодами, а не навсегда        | постоянное ухудшение убивает ритм партии                              |
| Перки после заправки                  | до них каждая заправка только ухудшала условия                        |
| Барьеры на обочинах, а не на полотне  | дороги должны читаться как безопасный быстрый путь                    |
